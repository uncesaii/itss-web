# Security Policy

## Supported Versions

Only the latest code on the `main` branch is supported.

| Version | Supported |
| --- | --- |
| `main` | Yes |
| Older branches, forks, and modified deployments | No |

## Reporting a Vulnerability

Do not report security vulnerabilities through public issues, pull requests, or discussions.

Report security issues privately to:

**itss.cvsusc@gmail.com**

Use the subject line:

```text
[SECURITY] ITSS Website - short description
```

Include as much of the following as possible:

- A clear description of the vulnerability
- The affected page, file, dependency, or URL
- Steps to reproduce the issue
- The potential impact
- Screenshots or logs, if they do not contain sensitive information
- Any suggested fix or mitigation

## Rules for Security Testing

- Do not access, modify, delete, or exfiltrate data that does not belong to you.
- Do not disrupt the website or its hosting.
- Do not perform denial-of-service testing, social engineering, or attacks against third-party services.
- Test only against systems and deployments you are authorized to test.
- Keep vulnerability details private until the issue is reviewed and resolved.

## What to Expect

The webmaster will review the report, confirm the issue where possible, and coordinate a fix. Valid reports may be acknowledged after the issue has been resolved.

General bugs and feature requests should follow [CONTRIBUTING.md](CONTRIBUTING.md). Security issues must never be submitted as public pull requests.
